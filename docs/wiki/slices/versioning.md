# Срез: versioning

Версионирование API и разбор версии клиента по User-Agent.

## Границы

Префикс `/v1` для всех маршрутов и плагин, который разбирает заголовок User-Agent (платформа и версия приложения), включая мягкое требование обновиться. Своих таблиц по сути нет; минимально поддерживаемые версии держим в конфигурации.

## Владеет таблицами

Ничего (плагин и конфигурация). Разбор кладёт `request.platform` и `request.appVersion` на запрос.

## Касается

- `src/router.ts` — регистрация всех маршрутов под префиксом `/v1`.
- Все маршруты — проходят через плагин.
- Срез [feature-flags](feature-flags.md) читает разобранные платформу и версию.

## Эндпоинты

Своих нет. Добавляет поведение: если версия приложения ниже минимально поддерживаемой, вернуть понятный ответ «нужно обновиться» (например код 426) до попадания в бизнес-логику.

## Зависит от

Ничего. Брать можно сразу, параллельно с `auth` и `player`.

## Что сделать

1. `plugins/apiVersion.ts`: разбор `User-Agent` вида `GonnaPlay/2.3.0 (ios)` → `request.platform`, `request.appVersion`.
2. Регистрация маршрутов под `/v1` в `src/router.ts`.
3. Гейт минимальной версии: конфигурация минимально поддерживаемых версий по платформам, ответ «обновись» при её нарушении.
4. Публикация разобранных значений для среза feature-flags.
5. Замечание по Postman (решение Р6): коллекция генерируется из OpenAPI, который отдаёт `@fastify/swagger`, а не ведётся вручную — оформить шаг генерации (импорт OpenAPI в Postman или скрипт в CI).

## Готово когда

Все маршруты под `/v1`; User-Agent разобран в `request.platform` и `request.appVersion`; запрос со слишком старой версией получает ответ о необходимости обновления; значения версии доступны для флагов.
