# Gonna Play — вики бэкенда

Это источник правды по бэкенду `gonna-play-backend`: зачем приложение, как устроена архитектура, какая модель данных, какие решения приняты и кто над чем сейчас работает. Вики нужна, чтобы несколько сессий Claude Code (или разработчиков) могли работать параллельно, не теряя контекст и не строя конфликтующие вещи.

## С чего начать

Любая сессия перед работой читает общий каркас:

1. [overview.md](overview.md) — что за приложение и из чего собрано.
2. [architecture.md](architecture.md) — рантайм-архитектура, слои, поток запроса.
3. [data-model.md](data-model.md) — сущности, связи, перечисления. **Это источник правды по модели данных.**
4. [decisions.md](decisions.md) — журнал принятых решений и открытых вопросов.
5. [conventions.md](conventions.md) — как писать код в стиле проекта.

Диаграммы лежат рядом: [../diagrams/A-architecture.png](../diagrams/A-architecture.png) (рантайм) и [../diagrams/B-domain.png](../diagrams/B-domain.png) (модель данных). Исходники `.excalidraw` там же — их можно открыть и править на excalidraw.com.

## Как работать параллельно

Работа нарезана на **срезы** (`slices/*.md`). Каждый срез самодостаточен: в нём границы, какие таблицы он создаёт и каких касается, эндпоинты, зависимости от других срезов и критерий готовности. Чтобы взять срез в работу, сессии достаточно прочитать общий каркас (пять файлов выше) плюс один файл своего среза — этого хватает, чтобы не потерять контекст и не лезть в чужие таблицы.

Координация идёт через [PROGRESS.md](PROGRESS.md) — доску состояния. Протокол простой:

1. Открой [PROGRESS.md](PROGRESS.md), выбери срез со статусом «не начат», у которого закрыты зависимости.
2. Поставь ему статус «в работе» и впиши владельца (имя ветки или идентификатор сессии). Закоммить это изменение первым — так другие сессии сразу видят, что срез занят.
3. Работай по файлу среза. Возникающие детали (точные контракты эндпоинтов, поля) дописывай прямо в файл среза — он растёт вместе с реализацией.
4. Закончив, поставь статус «готов» и отметь, что появилось (таблицы, модуль, эндпоинты).

Срезы упорядочены по зависимостям: сначала `auth` (его ждут все остальные), затем `player` и `matches`, потом `teams`, `notifications`, `venues-media`, `feature-flags`, `versioning`.
