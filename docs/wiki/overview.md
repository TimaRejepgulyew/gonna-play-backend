# Обзор

## Что за приложение

Gonna Play помогает людям находить любительские футбольные матчи и записываться на них. Организатор создаёт матч на площадке в конкретное время с форматом (пять на пять, семь на семь, одиннадцать на одиннадцать) и лимитом игроков. Игроки записываются на свободные места, при заполнении попадают в лист ожидания. Перед игрой матч разбивается на две равные команды с учётом уровня и позиций игроков. Уведомления о напоминаниях, заполнении и разбивке уходят игрокам, в том числе через Telegram.

Рейтинг игрока — самооценка: игрок сам указывает уровень (junior, middle, senior, legend). Вычисляемого рейтинга и оценок после матча пока нет (см. [decisions.md](decisions.md)).

## Стек

Рантайм — Node.js 24 (действующий LTS «Krypton»). Версия зафиксирована в трёх точках: `.nvmrc`, пол `engines.node >=24` в `package.json` и базовый образ `node:24-alpine` в `Dockerfile`. Бэкенд собран на Fastify 5 в режиме ESM на TypeScript 7. Данные — PostgreSQL через Prisma 7 (driver adapter `@prisma/adapter-pg`), плюс Redis (кеш, хранение refresh-токенов, rate-limit). Схемы запросов и ответов описываются на TypeBox и подключаются через `@fastify/type-provider-typebox`. Вход — JWT (`@fastify/jwt`), вход через Telegram — задел на будущее. Логирование — pino. Документация API — `@fastify/swagger`, спецификация отдаётся на `GET /docs/json` (UI Swagger не подключён), из неё генерируется коллекция Postman. Медиа (фото площадок, аватары) по плану хранятся в объектном хранилище и отдаются через CDN — модуля хранилища в коде пока нет.

Точные версии зависимостей всегда сверяй с `package.json` — он источник правды.

## Модули

Каждый ресурс — отдельная папка `src/<resource>/` со слоями controller → service → repository → model (см. [conventions.md](conventions.md)).

Реализованы: `auth` (регистрация и вход по email, токены), `user` (учётные записи), `player` (игровые профили), `match` (матчи и запись участников с листом ожидания), `location` и `field` (комплексы площадок и поля внутри них). Модуль `rating` в коде тоже есть, но это отклонение от решения Р1 к удалению, а не часть целевого состава.

Ещё не заведены (ждут своих срезов): `team` — разбивка на команды; `notification` — уведомления и каналы доставки; `storage` — обёртка над объектным хранилищем; feature flags.

Сквозные плагины сейчас: авторизация (`authenticate` / `authorize`), swagger, prisma, redis; rate-limit подключён не плагином, а per-route утилитой. Ещё не сделаны: версионирование по User-Agent (`/v1`), feature flags, единый обработчик ошибок, объектное хранилище, фоновые задачи на `node-cron`.
